## 未提交工作 B：PartSouq bounded resume

### 根因

run 5 已有 exact 10,000 membership，但仍有兩個 `crawl_state=error`。既有 resolver 會續用 run 5；
crawler 計算 remaining=0，無法再取得額度修復 failed scope，因此形成永久重試，不能發布。

### 已落盤草稿

- `src/partsouq_catalog/repositories.py`
- `tests/test_partsouq_bounded_limit.py`

草稿新增 `exhausted_with_failures`：membership 已達 target 且仍有 scope error 時，拒絕續用舊
logical run、將 evidence fail-closed 標為 rejected、保留舊 raw／artifact／lineage，再讓
scheduler 建立新 logical run。

### 已測

- focused unit：`6 passed`。
- `partsouq_catalog_test` 真 MySQL參數化：`3 passed`。
- 完整 bounded test file：exit 0。
- production `repositories.py` strict mypy、Ruff、format、diff-check：通過。
- 獨立 review 確認 scheduled 路徑的交易與 evidence preservation 正常。

### 尚未修正

direct bounded 若明確設定 `PSQ_BOUNDED_RUN_KEY`，會略過 resolver，仍可能重開已耗盡且有錯誤的
run。正式 scheduled 10k會拒絕 explicit key，所以不是正式排程 P1；但 direct 行為仍不一致。

最小修法：禁止所有 bounded run 使用 explicit key，或讓 explicit key 經過同一 compatibility
gate。補 `Crawler.run()` regression、重跑 bounded unit／真 MySQL、獨立 review後，再單獨
commit／push。修完前不得啟動正式 10,000。
