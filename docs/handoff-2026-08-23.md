## NHTSA 未提交草稿的已知 P1 blocker

### 1. Atomic publish 後 child 非零退出會反向破壞 scheduler 狀態

目前 repository 會在同一交易完成 current publish、domain completed、scheduler child completed。
但 child 若在 commit 後、Python 正常 exit 前被 signal／非零退出，scheduler `_record_finish()`
仍可能把該 child 改成 failed，形成：current 已發布、domain completed、child failed。

建議：atomic completed tuple 應是 outcome authority；觀察到的非零 OS exit 保留在 output 作診斷，
不可反向覆寫已提交的一致狀態。需補 unit、真 MySQL及 process-level regression。

### 2. Heartbeat lifecycle 仍有錯誤邊界

- Bulk publish 清除 token 後，晚到 heartbeat 可能誤報 `LeaseLost`。
- API／VIN 的 heartbeat enter 在 `try` 外；enter 失敗會留下 running lease。
- API／VIN cleanup 的 `heartbeat.close()` 可能遮蔽原始錯誤／取消，並跳過 terminal CAS。
- `thread.join()` 沒有 timeout；DB stall 最長可能卡到 connection timeout。
- heartbeat repository close 失敗需正確回報，不能只逃離 thread。

### 3. Stale worker 仍可做中間 artifact mutation

最終 publish 有 lease gate，但 create/store/reset/insert/quarantine 等中間寫入沒有全部帶 lease。
expired takeover 後，舊 worker 仍可能污染尚未發布的中間狀態。需讓中間 mutation 綁定 active
lease，或改成 run-scoped staging 並由 active lease 才能 promote。

### 4. 長 finalize transaction 可能跨過 lease expiry

程式在 publish 前停 heartbeat，交易尾端又核對 expiry。若 finalize 太久，可能自行過期並
rollback。需確定 renewal／expiry 契約，並以可控短 lease 真 MySQL test 證明。

### 5. 格式 gate 未完成

`tests/crawler/integration/test_nhtsa_mysql_sync.py` 仍會被 `ruff format --check` 判定需要格式化。
完成上面 P1 修正後再一起格式化、重跑全部 gate。
